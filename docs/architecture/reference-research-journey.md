# Reference research journey: existing APIs, saved artifacts

This bounded reference is a usability acceptance exercise, not a new pipeline,
feature schema, benchmark, calibration study, or generalization claim. It makes
consumer choices visible instead of adding a disconnected metadata framework.

## Run

From the repository, with NumPy/SciPy, scikit-learn and meshio available:

```sh
python -m examples.reference_research_journey --output-dir /a/new/private/journey
python -m pytest tests/test_reference_research_journey.py -q
```

The output directory is required and must not exist. The script refuses overwrite,
including an existing empty directory. A failed run may leave partial evidence;
inspect it, then use a new directory. No optional dependency is added. Native training is documented in
[native Dataset training usage](native-dataset-training-usage.md), and the named consumer in
[named inference usage](named-inference-usage.md). Run via `python -m` from the repository or with FiberNet installed. Pickle
reload is restricted to the trusted artifact generated by the same invocation;
never substitute a downloaded or otherwise untrusted pickle.

## What actually runs

1. Generate ten deterministic four-node square graphs with varying side lengths
   (0.010–0.019 m) and radii (0.00010–0.00019 m), zero internal points.
2. Persist with `StructureGraph.save_json` and reload with `load_json`. Five
   fixtures have sparse node/edge IDs. Native save canonicalizes record order;
   for these five, the script writes a second native JSON file with reversed
   record order and reloads that file, explicitly testing row/ID differences.
3. Run linear 2D beam-frame FEM through `fn.simulate`, with global E=1e6 Pa,
   nu=0.3, stretch ratio=1.01 (engineering strain=0.01) and `pct=.5`;
   save detailed `SimResult`, then reload.
   The radius and geometry are in metres, so forces are N. E/nu are passed
   explicitly; graph Material values are **not** used automatically. The graph
   declares matching E=1e6 Pa/nu=0.3 for artifact coherence; the reference checks
   that declaration after native reload and through the VTU material indices
   and manifest. This is not a backend precedence change. On a
   four-node square, pct=.5 grips both left and both right nodes. The default
   pct=.10 would grip only one node per side, a different experiment.
4. Separately run `solve_linear_transport`: every edge receives an explicit
   conductance of 0.20+0.01×sample_index S, with left potentials 1 V and right
   potentials 0 V. Geometry/material never infer conductance. Save and read
   the electrical result JSON with its own schema and explicit V/A/W/S units.
   This fully prescribed four-node example does not test an interior-node
   transport solve. Electrical fields are not mechanical labels.
5. Extract `SnapshotFeatureExtractor.extract_graph` features and save the full
   snapshot. Explicitly select/rename total_length_m and pore_area_mean_m2, and
   derive mean_cross_section_area_m2 from graph radii. The snapshot extractor
   itself does not infer radius or units. Contact is not requested. Fracture
   strength is unavailable in this linear model; both remain null with status
   in sample metadata, not zero labels or selected model features.
6. Build `DatasetSample` objects and `FiberNetDataset` with explicit ordered
   feature and target names. Save arrays and metadata, reload, assert equality,
   and call the existing `to_csv`. The actual target is max_axial_force_N,
   the maximum absolute member axial force, not the summed grip reaction,
   generated by the mechanical solver; its elementary value EA×0.01 is also
   checked per sample. No electrical quantity is a learning target.
7. Train directly on the loaded `FiberNetDataset` through `fn.train_model`,
   using raw feature names and `target="max_axial_force_N"`, LR, `test_size=.3`
   and explicit `split="row"`. Keep `dataset.csv` as an interoperability export;
   it is not reparsed for training. Select the existing per-row metadata keys
   `length_unit`, `target_unit` and `target_meaning` for the model's provenance.
   The fixed seed 42 gives train rows `[0,7,2,9,4,3,6]` and test rows `[8,1,5]`.
   This is a row holdout of related synthetic squares, not independent-origin
   validation. No usable origin groups are inferred from their unique IDs.
8. Reload only that newly created trusted pickle. Reverse the raw feature
   order in mapping records, retain sample-ID/label extras, then call
   `fn.predict_named(artifact, records, extra_columns="ignore")`.
   The wrapper selects the **artifact's saved feature list**.
   Predict all ten rows as a reload consistency check; these ten predictions
   are not independent evaluation. Match predictions to sample IDs in the same
   original row order. Deliberately pass an equal-width wrong-order ndarray
   directly to the bare estimator to demonstrate its legacy boundary.
9. Export retained mechanical displacements/axial forces and electrical
   potentials/currents using `write_vtu_bundle`'s ID-keyed field arguments.
   Reload each actual network.vtu through meshio; verify node IDs, edge IDs,
   connectivity and every exported field against the source result identity.
   FEM node rows are insertion-ordered; electrical nodes are sorted. The five
   reversed fixtures ensure those orders really differ. These exported fields
   are solver results; a graph-level ML prediction is not silently assigned to
   individual nodes or edges.

## Concrete evidence and limits

The reference run produces ten complete sample folders, dataset/features.npy,
dataset/labels.npy, dataset/metadata.json, dataset.csv, model.pkl,
predictions.json and summary.json. It reads back all ten VTUs. The direct native
path is checked against the trivial linear force–area relation and ten related
synthetic squares. Very small fitting errors or R² near one establish API
usability only, not science, calibration, accuracy on real networks, or
out-of-family generalization. Exact numerical results are recorded in each new
run's summary; the native path avoids CSV float parsing, so roundoff need not
match historical CSV-trained artifacts.

New native pickles retain the v1 keys `model`, `features`, `metrics`,
`artifact_version: 1` and raw `target: "max_axial_force_N"`. Native metrics add
`target` and `training_data`, including original row indices/sample IDs, actual
split indices, and snapshots of the three selected metadata fields. The stored
feature list is:

- total_length_m
- mean_cross_section_area_m2
- pore_area_mean_m2

Existing CSV-trained artifacts remain prefixed, with their existing metrics and
fitted predictions unchanged. This example does not migrate, rewrite or load
those historical pickles. Its CSV export still contains `feat_`/`label_` headers.

The named wrapper validates names, coverage, finite real selected values and a
finite single-target prediction vector. Default extra rejection catches IDs and
labels; the reference deliberately ignores these extra fields. It validates the
artifact envelope version, not units or a physical/feature schema. The copied
metadata are source assertions. Units encoded in feature names remain caller
conventions. The bare estimator still accepts equal-width wrong-order matrices;
the reference deliberately verifies that doing so changes predictions. Its API
is unchanged.

The native boundary validates only selected feature/target values; unavailable
contact/fracture metadata remains null with status in the saved Dataset. It is
not silently converted to numerical zero. CSV does not carry those metadata.
Dataset persistence uses staged writes and ordinary-exception rollback, with
explicit limits on crash durability and concurrent access; see
[Dataset persistence usage](dataset-persistence-usage.md). This reference does
not change that contract.

## Remaining consumer boundary

Named-column inference closes source-column ordering and coverage errors for
named inputs. It cannot verify units, physical meanings, provenance, calibration
or model fitness. A future schema-bearing producer/consumer contract needs
explicit comparison and migration rules before such checks can be advertised.
The new API does not deserialize files; callers remain responsible for loading
only trusted artifacts. See [usage and compatibility](named-inference-usage.md).
