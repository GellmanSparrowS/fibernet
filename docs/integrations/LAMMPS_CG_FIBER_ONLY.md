# Fiber-only 3-D coarse-grained networks

Use the public `CGRequest`, `prepare_cg`, and `simulate` APIs for a bent or
branched network without an artificial projectile. This extends the existing
harmonic-bond/cosine-angle model, not its physical scope or a new force law.

## Explicit request

Set all four fields explicitly when adapting an existing request:

```python
projectile_node_id=None
projectile_pairs={}
pair_encoding=None
profile=None
```

The first two remain required `CGRequest` arguments, in their original
positional locations. The null projectile is admitted only with an empty pair
mapping and no pair encoding or network profile. `False`, a floating-point ID,
and an unknown node ID are not aliases for `None`. An integer projectile still
must name an isolated graph node; its generated bytes and semantics are
unchanged even when its pair mapping is empty.

The authoritative `StructureGraph` must be 3-D. Its actual nodes, straight
edges, geometry and stable IDs are preserved. Supply one positive nodal mass
per node, one `HarmonicBond` per edge, and an explicit mapping of stable angle
IDs to `CGAngle` records. Each angle references its three distinct graph nodes
and its two incident graph edge IDs. Branches do not automatically create
angles, and no node, edge or angle is invented by the compiler.

This branch retains the small-pilot limits: 2–64 nodes, at most 128 edges and
128 angles, 0–1000 steps, every step sampled, and the existing 1 MiB prepared
text ceiling. Network profiles and their larger bounds are unavailable here.
The existing explicit cached-neighbor option remains available within these
same small-pilot limits; it does not introduce nonbonded forces.

## Complete executable example

`examples/cg_bent_branched_network.py` builds seven noncoplanar beads, six
bonds and five bent triplets. The degree-four junction uses stable node 205;
the node IDs are 101, 205, 309, 413, 517, 621 and 725. Stable edge and angle IDs
are also explicit. Node 101 is fixed by excluding it from integration. The
initial bond lengths equal their supplied equilibrium lengths, while the bent
triplets store cosine bending energy. Coefficients are illustrative SI inputs,
not fitted silk or continuum-beam parameters.

From the source root, with an already qualified and pinned CLI runtime:

```sh
python -m examples.cg_bent_branched_network \
  --runtime-json /absolute/path/runtime.json \
  --output /absolute/path/new-output
```

The command runs 20 steps at `1e-7 s` by default. `--steps 0` requests static
force/energy evaluation; `--steps` and `--timestep-s` can be supplied within
the contract bounds. It executes native LAMMPS and requires an existing
compatible runtime. It does not install, discover or silently substitute one.
Importing the module or calling `build_case()` does not launch native code.

`runtime.json` contains the exact fields of an already prepared `RuntimeSpec`,
for example the JSON serialization of `dataclasses.asdict(runtime)`. The
`file_sha256` and `environment` arrays are restored to tuple pairs. Runtime
admission checks the explicit executable paths, identity pins, expected
version/banner and supported platform. For `cli_serial_static`, the existing
contract requires a supported Linux x86_64 static executable, a pinned Python
worker, empty package directory and no environment overrides. The example does
not manufacture evidence that a binary has the required styles.

You can alternatively pass a qualified `RuntimeSpec` object directly:

```python
from examples.cg_bent_branched_network import run_example
result = run_example(runtime, "/absolute/path/new-output")
```

The output directory must be new. It contains the original `graph.json`, the
owned native task directory, `result_detailed.json` and `result_summary.json`.
The example calls public `simulate(..., backend='lammps', mode='dynamics',
record_state=True)`, saves both forms through `SimResult.save`, reloads through
`SimResult.load`, and checks exact export equality. Both forms retain the null
projectile and original stable IDs. Rehashed forged null-plus-pairs results are
rejected. Summary exports intentionally do not contain the full trajectory or
enough graph incidence to replay compilation on their own.

## Model and force interpretation

- Harmonic bond energy is `0.5*k*(r-l0)^2` with `k` in N/m and `l0` in m
- Cosine angle energy is `K*(1+cos(theta))`, with `K` in J and a straight-triplet
  minimum; a curved initial shape is generally not stress free
- `edge_forces` and `max_force` are axial harmonic-bond quantities only
- Native `dynamics_state.nodal_forces` and potential/total energy include angle
  bending; the initial axial edge forces can be zero while nodal forces and
  bending energy are nonzero
- `final_max_net_nodal_force_N` includes the native net nodal contributions;
  it is distinct from axial `max_force` and is not a general reaction-force API
- Pressure is a global box-pressure tensor in Pa, not a material stress tensor

This model has translational bead motion and selected angular interactions.
It is not a continuum beam with calibrated EI, rotational degrees of freedom,
or torsional stiffness. It has no nonbonded interactions in this branch: beads
can overlap, fibers can cross, and excluded volume, continuous contact, adhesion,
fracture and impenetrability are absent. A 3-D geometry alone does not supply
any of these mechanics.

The generated contract truthfully declares `pair_model='none'`, harmonic bonds,
cosine angles, and only the `zero` pair style. All type pairs are excluded.
MOLECULE is required for the angle/bond model; Morse and EXTRA-PAIR are not
required by the null branch. A runtime must separately provide the declared
styles, including `zero` and `nve`.

## Bounded task lifecycle

The synchronous `simulate` call uses the same `LAMMPSTask` as the harmonic CLI
backend. To own an asynchronous run explicitly, compile first and then create
`LAMMPSTask(prepared, runtime, new_workdir, limits)`. Call `start()` once, inspect
`state`, call `wait(timeout=...)` for completion, and use `cancel()` followed by
`wait()` to finish cleanup. A wait timeout does not stop the independent
watchdog. A completed task exposes a stable-ID `LAMMPSRunResult` in `result`;
failed or cancelled tasks expose `error` rather than a fabricated trajectory.
Cancellation does not support restart or resume.

CPU, address-space and individual-file ceilings apply to the child. The
aggregate output ceiling is polled and checked again at completion, not a hard
filesystem quota; transient overshoot is possible. Native execution remains
limited to qualified Linux x86_64 CLI runtimes. Preparing inputs and checking
synthetic result contracts do not launch the engine.

## Verification boundary

The retained native acceptance covers this exact seven-bead, six-bond,
five-angle noncoplanar branched example on LAMMPS 22 Jul 2025 Update 4,
using a pinned serial static CLI executable. Three completed cases were
independently checked: static evaluation, 100 steps at 1e-7 s, and 200 steps at
5e-8 s. Both moving cases cover 1e-5 s and save every integration step.
The maximum total-energy drifts were 1.8738469179178458e-22 J and
4.6846204280515225e-23 J. The fine/coarse drift ratio was 0.2500001672;
this is an observed two-grid refinement, not a convergence-order theorem.

Stable IDs, generated inputs, native force/energy records, fixed nodes,
independent scalar references and detailed/summary save-reload contracts were
checked. `tests/fixtures/lammps_cg_fiber_only_acceptance.json` records the runtime,
input/output digests and bounded evidence scope. The publication tests compare
these retained input digests without rerunning LAMMPS. Synthetic parser and
owned-task mocks remain contract tests, not additional physical validation.

No general-network, long-run, finite-strain, continuum EI/torsion, excluded-volume,
adhesion, fracture or impenetrability claim follows. Larger harmonic and CG
profile helpers retain their explicit compilation limits, but the null-projectile
branch does not admit a network profile. The separate MCP physics-task adapter
and its 189-node/812-edge harmonic example are not included in this release.
The existing five MCP tools remain unchanged. Native live cancellation is not
claimed from a completion-race observation.

## Runtime packages and license

The pure-fiber branch needs `atom_style angle`, `bond_style harmonic`,
`angle_style cosine`, `pair_style zero`, and `fix nve`. Upstream's
[cosine-angle documentation](https://docs.lammps.org/angle_cosine.html)
specifies K[1+cos(theta)] and the MOLECULE package.
[Pair zero](https://docs.lammps.org/pair_zero.html) supplies neighbor bookkeeping,
not pair forces or pair energy. Morse and EXTRA-PAIR are not needed here.
Current upstream documentation and the pinned tested runtime are distinct;
check required styles for the actual selected executable.

No engine binary, wheel, MPI library or LAMMPS physics implementation is bundled,
and this feature adds no Python dependency or automatic installation step.
LAMMPS remains a separate GPLv2 engine. See the existing
[provider and redistribution notice](../../fibernet/integrations/LAMMPS_NOTICE.md)
and [upstream license guidance](https://docs.lammps.org/Intro_opensource.html).
Optional execution is not a blanket licensing exemption. Direct Python-library
linkage and bundled combined distributions are outside this CLI release and
require their own licensing review.
