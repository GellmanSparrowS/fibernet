# Shared target-curve inverse workflow

The target-curve search now runs in the existing `fibernet` package through `CurveInverseDesigner` or `run_curve_inverse`. FiberScope's inverse-design panel calls the same search routine through a compatibility adapter that supplies its registered unit keys. The graph builder is passed by the caller, so the optimizer does not depend on APP state; the public example `examples/curve_inverse_workflow.py` builds graphs solely with the package's planar manufacturing API and writes an atomic JSON summary.

The search uses a two-stage, fixed-budget procedure. It first evaluates either the supplied fixed unit or each supplied candidate unit with the initial deformation spectrum. It then refines two reference-fiber displacement control points and one perturbation parameter using a cross-entropy-style elite update. The seeded candidate sequence contains broad initial samples, a local fraction around the current mean, and a persistent global fraction; the elite spread is bounded below to avoid immediate collapse. The callback records each candidate, objective, and running best, and a stop callback is checked between evaluations. A custom evaluator may replace the default reduced-solver objective while retaining the optimizer and record format.

For the default numerical path, every candidate is simulated with the shared reduced spring/bending/contact solver at 60 load increments, 6000 time steps, a 0.7 loading ramp fraction, drag coefficient 200 and the requested terminal stretch. The force curve is restricted to strictly increasing stretch samples before resampling onto 24 normalized load positions. The J, C and linear targets are deterministic normalized shapes. Curve objectives minimize the root mean square distance between the normalized simulated and target curves. Scalar objectives instead maximize or minimize peak raw reaction, early-curve rise or integrated force with respect to stretch, according to the requested target. Those scalar quantities inherit the reduced solver's units and assumptions; the integral is a numerical work proxy and is not an experimentally measured toughness. An initial migration smoke test exposed an omitted explicit drag parameter because the library solver's default was 1500; setting it to the APP's 200 restored exact equality across all 24 objectives in a seeded chiral search. The regression suite now compares every solver configuration field across the two entry points.

The method retains existing FiberScope behavior, including fixed-unit refinement, seeded sampling and event callbacks; the APP's `fast_cfg` compatibility function still returns its previous configuration type for external worker callers. The public library entry point requires explicit `unit_keys` when no fixed unit is given so an installed library does not silently substitute a different family list. The example limits budget to 30, grid size to four and graph size to 1000 nodes/1500 edges. The optimization does not certify global optimality, continuous printability, experimental target matching or uncertainty of the selected design. External material calibration and held-out objectives are needed before scientific performance claims.
