# FiberNet–FiberScope 能力与开源质量审计（2026-09-24）

## 判断口径

“库支持”要求用户安装 `fibernet` 后，在不导入 `FiberScope` 或 Qt 的情况下，通过公开 Python API 完成相同计算，并有可运行示例、参数说明、确定性与边界测试。仓库里存在源码、网页能点击，或 APP 调用了库的某个基础生成器，均不算该功能已迁入库。GUI 中的绘图与交互可作为适配层，但相同的科学计算应由可复用库提供。

## 当前可核验状态

以下是截至本地 2026-09-24 候选封盘的状态，后文“已发现的问题”保留开发时的历史记录，不能把其中的旧测试数当作当前发布结论。原仓库本地工作分支库全套为 368 通过、19 跳过，APP 本地及 GitHub Windows CI 均为 25/25；库端 GitHub CI 在 Linux、macOS、Windows 与 Python 3.9–3.12 的 12 个组合通过。4.2.0 wheel 在 Python 3.10 隔离路径实跑自定义单元、闭合路线、平行梁及快照特征，新冻结 APP 通过依赖探针、冒烟、Windows 可携带性与干净目录复制冒烟。七段主页 GIF 具有可编辑关键帧和源码/结果哈希，五页本地论文 PPT 的输出与输入 SHA 匹配。源码尚未发布为新 PyPI/APP 版本，GitHub 源码更新由本轮提交记录核对。

公开 API 已有独立示例：平面/曲面连续路线、APP 兼容自定义单元 JSON 持久化、OBJ 读入、逐面曲面映射、实体及路线导出、简化拉伸时序与阈值招募、快照结构/孔隙/有限宽接触特征、物理标注数据流、三目标代理训练和目标曲线逆设计。研究脚本还可对四拓扑的等长度欧拉路线删除进行逐案例原子续跑，但该脚本并非稳定的通用删边库 API。代理/RL 全设计路径、设备交接与 AI 助手仍未成为相同语义的公开库工作流。后续需在独立机器和操作系统上测量安装与典型任务成功率，并对科学指标补独立模型/实物验证；不能把本机通过测试等同于面向广泛用户的正式验收。

## 已发现的开源可用性问题

- `pyproject.toml` 为 4.1.6，`fibernet.__version__` 和 `fibernet.version` 原为 4.1.2；已统一并加版本契约测试。
- README 的 FEM 示例访问 `max_displacement`，原便捷结果字典缺失；已补充并加真正运行该示例的测试。
- APP 曾把制造网络的独立双纤维压成简单图，零内部点时出现边数不一致；独立统一检出已支持显式平行边，4 基元 × 3 点数图契约回归通过。
- 完整 APP 回归最终为 25/25（Python 3.10 `ml310`，Windows）；库广泛测试此前为 285 通过、19 跳过、10 环境相关失败。后者不能当作发布通过，需要隔离依赖与平台重测。
- 根目录 README 将 APP、旧版库介绍和静态图片串联，且公开 API 能力与 APP 实现存在明显差距。主页改版前要先修正能力声明，再制作来源可复核的动画。
- 本地新版主页草案为 `docs/README_VNEXT.md`，动图、SVG 和数据谱系 JSON 位于 `docs/media/`。动画已做帧数、尺寸、SHA 和注释检查；仍需逐帧视觉审查。以上未更新 GitHub。
- 本地草案现有四拓扑形变谱与时序招募两段可重跑动画；前者是几何展示，后者是应变阈值图，均不得写成已验证材料性能。轮廓/文字 SVG 可编辑，媒体自动 QA 由 `scripts/check_homepage_media.py` 完成。
- 迁移渗流后完整 APP 回归为 25/25，库新分析模块 7/7；库顶层在装有 Taichi 时会顺带导入它，但模拟 Taichi 缺失的导入测试仍通过。性能与干净安装待测。
- 库端广泛回归在正常 Windows 权限下为 297 通过、19 跳过、7 失败。剩余七项属于当前 base PyTorch 无 LAPACK SVD 的可微计算路径；该环境的 2×2 SVD 自检失败，而 `ml310` 的对应自检通过。`ml310` 上的较短物理测试可运行，两个优化循环超时中止；完整交叉环境验证仍是发布门槛。
- 构建审计发现旧 setuptools 无法解析原 `project.license` 字符串及 `license-files` 字段；调整兼容元数据后，wheel 成功构建并包含 LICENSE 和新增分析模块。隔离路径导入小例子通过，构建临时物已清理。干净虚拟环境安装仍待做。
- 平面及曲面制造计算已迁入 `fibernet.gen`，APP 使用共享编译器；库独立示例保存两种网络的参考/实际坐标、边与闭合路线。旧 e2v9→e2v10→e2v11 黄金 40 数值数组两次比较均无差异，三个研究检查点每次只在 `cases` 严格相同后原子替换。曲面接口验证了有限坐标、四顶点整数索引、合法范围与不重复顶点；闭合路线不代表物理可打印。
- 简化拉伸求解器现在为 `fibernet.sim` 公共 API，APP 使用同一 NumPy 数值核心。e2v11→e2v12 的四例 40 数组最大相对偏差为零；三项旧干预研究和两项新动态招募研究共 72 个案例在重算后严格相同才替换检查点。主页五段动画的 GIF/SVG/来源哈希已重生为 e2v12 并通过媒体 QA。独立库示例可保存完整节点轨迹、边应变、原始反力和招募掩码。
- 公开易用 API 实跑发现 `simulate(..., backend="fem")` 原无有效分支，`batch_simulate` 调用了该分支并读取不存在的 `E_star/nu_star`；已改为真实 FEM `SimResult`，批量 CSV 输出已验证存在的 `max_force/max_displacement/energy`。`SimResult.save` 的 FEM 元数据含 NumPy 数组，原 JSON 写入会失败并可能留下残缺文件；现序列化并原子替换，已有保存/读取回归。Windows GBK 终端下 `show` 的符号提示会触发编码异常，现用 ASCII 文本。端到端示例和 11 项相关测试通过。FEM 仍未对实验校准。
- 后续进一步检出梁 FEM 快捷入口默认去重独立平行边，以及 FEM `max_force` 使用固定 0.05 半径换算轴应力的错误。公开拉伸入口现保留全部独立边，最大边力按真实截面/逐梁轴力计算，伸长比由变形后长度计算；解析双梁夹持反力与能量恰为单梁两倍。旧 18 案例的阈值贯通 18/18 与新结果一致，但旧力摘要为新值四分之一；旧结果保留作历史口径，新 `recruitment_fem_validation_parallel.json` 才是当前口径。`max_force` 不是夹持反力，`energy` 不是总弯曲功；方法见 `METHODS_BEAM_FEM_CONTRACT.md`。
- 主页本地草案现使用 3×3 扰动笼目结构的时序招募动画，并增加同一轨迹下三阈值对照；三段 GIF 均有可编辑关键帧 SVG、哈希清单和自动媒体检查。`docs/INTEGRATION_REPO_MAP.md` 解释它仍是原仓库的开发分支。

## 发布门槛

每个迁移模块至少有：(1) 一个小规模端到端公开 API 示例；(2) 与 APP 同参数的数值/拓扑一致性检查；(3) Python 3.10 安装验证；(4) 输入上限、异常与可取消/恢复长任务的约束；(5) 方法假设、单位和局限；(6) 对旧保存数据的兼容验证。发布包需从干净环境安装、运行 README 示例，检查 Windows/Linux 和无可选依赖场景。主页动画只展示同一版本可复现输出，并注明求解器与阈值。
